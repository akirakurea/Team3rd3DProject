1. 우리가 직접 만든 커스텀 C# 스크립트 블랙보드
🟢 장점
가볍고 빠름: 유니티의 패키지 레이어나 추상화 과정 없이 C# 변수에 직접 접근하므로 연산 속도가 가장 빠르고 직관적입니다.

코드 자유도 높음: 블랙보드 안에 단순 변수뿐만 아니라, GetDistanceToPlayer() 같은 계산 메서드나 프로퍼티 로직을 자유롭게 넣을 수 있습니다.

BT 원리 학습 완벽 지원: 행동 트리가 내부적으로 데이터를 어떻게 주고받는지 구조를 100% 직접 제어하고 이해할 수 있습니다. (포트폴리오 작성 시 원리 설명에 매우 유리)

🔴 단점
시각화 부족: AI가 지금 어떤 변수를 참조하고 움직이는지 비주얼 그래프로 보려면 커스텀 에디터를 직접 짜거나 인스펙터를 따로 열어봐야 합니다.

2. 유니티 6 공식 Behavior 패키지 블랙보드 에셋
🟢 장점
비주얼 에디터 지원: 노드 그래프 창에서 + 버튼만 누르면 Transform, float, bool 등의 블랙보드 변수를 스크립트 작성 없이 즉시 추가할 수 있습니다.

실시간 디버깅 최고: 게임 실행 중 어떤 변수가 true로 바뀌고, 어떤 노드가 평가되고 있는지 그래프 상에서 파란색/초록색 불빛으로 실시간 확인이 가능합니다.

기획자 친화적: 프로그래머가 C#으로 노드 블록만 만들어주면, 기획자가 에디터 상에서 블랙보드 변수를 엮어 AI 행동 패턴을 마음대로 조립할 수 있습니다.

🔴 단점
C# 접근 시 보일러플레이트 코드 발생: C# 코드에서 이 블랙보드 변수값을 가져오거나 수정하려면 패키지 전용 API (BlackboardVariable<T>)를 거쳐야 하므로 코드가 약간 복잡해집니다.

패키지 의존성: 프로젝트 버전 업데이트나 패키지 구조 변경 시 대응이 필요합니다.

💡 포트폴리오 및 학습 관점에서의 조언
현재 C#/유니티 프로그래밍과 게임 아키텍처를 공부하시는 단계라면, 지금처럼 순수 C#으로 블랙보드와 BT를 만들어보는 경험이 훨씬 더 값집니다.

원리를 아는 상태에서 도구를 쓰는 것과 도구만 쓸 줄 아는 것은 면접이나 실무에서 큰 차이가 납니다.

C#으로 BT 기초 프레임워크를 다 완성해 보시면, 나중에 유니티 공식 Behavior 패키지나 NodeCanvas 같은 상용 비주얼 플러그인을 접했을 때 "아, 내부적으로 결국 우리가 만들었던 그 클래스 구조로 도는 거구나!" 하고 5분 만에 적응하실 수 있습니다.
